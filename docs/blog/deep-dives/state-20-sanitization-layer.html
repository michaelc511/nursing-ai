In plain words

A sanitization layer (code that masks personal details and secrets before anything is saved) masks personal data and secrets before anything is saved: chat memory, logs, traces (step-by-step records of each request: what ran, how long, what it cost), vector stores (a database that finds text by meaning, using embeddings). Saved state (everything the app must remember to continue correctly) outlives the conversation, so whatever goes in can leak later.

In plain terms: blacking out names and account numbers before a document goes into the archive.

The problem it solves

Persistence creates liability (saved data can leak personal details or secrets): if memory or logs store emails, phone numbers, passwords or API keys (a secret code that lets the app use a paid service), you've built a data leak.

What the book proposes (in my words): always implement a sanitization layer (code that masks personal details and secrets before anything is saved) that scrubs secrets and personal data before writing state (everything the app must remember to continue correctly) to disk.

How to implement it (ServiceApps)

Illustrative example: no ServiceApps (a company platform for IT tickets, HR requests and help-center articles) instance is connected, so the scenario and data are made up. The code is a self-contained sketch; it was run on that made-up data on Nov 19, 2026, and the output below is from that run.

The setting. ServiceApps (a company platform for IT tickets, HR requests and help-center articles) Assist, an AI helper inside a company's ServiceApps (a company platform for IT tickets, HR requests and help-center articles) portal. Employees ask it IT and HR questions; it answers from knowledge-base (KB (knowledge base: a library of help articles)) articles, looks up the employee's own tickets (incidents (a ServiceApps ticket for something broken) like INC0012345) and requests, and keeps one conversation per employee and ticket.

The scenario. An employee pastes their email, phone, a password and an API key (a secret code that lets the app use a paid service) into a ServiceApps (a company platform for IT tickets, HR requests and help-center articles) Assist chat.

Steps.

  1. List the patterns to mask (emails, phones, IDs, passwords, API keys (a secret code that lets the app use a paid service)) plus known names.
  2. Run every text through redact() before saving to memory.
  3. Add a logging filter, so logs are masked automatically.
  4. Test it with fake data, like the example below.

The code (Python):

import re, logging, io
PATTERNS = [(re.compile(r"[\w.+-]+@[\w-]+\.[\w.]+"), "[EMAIL]"),
            (re.compile(r"\(?\b\d{3}\)?[ .-]\d{3}[ .-]\d{4}\b"), "[PHONE]"),
            (re.compile(r"\b(sk|pk|api)[-_][A-Za-z0-9]{16,}\b"), "[SECRET]"),
            (re.compile(r"(?i)password\s*[:=]\s*\S+"), "password: [SECRET]"),
            (re.compile(r"\b\d{3}-\d{2}-\d{4}\b"), "[SSN]")]
def redact(t):
    for rx, rep in PATTERNS:
        t = rx.sub(rep, t)
    return t

class RedactingFilter(logging.Filter):
    def filter(self, record):
        record.msg, record.args = redact(record.getMessage()), ()
        return True

buf = io.StringIO()
log = logging.getLogger("assist"); h = logging.StreamHandler(buf); h.addFilter(RedactingFilter())
log.addHandler(h); log.setLevel(logging.INFO)
msg = "I'm dana@example.com, 555-201-3344, password: Hunter2! and my key is sk_live1234567890abcdefXYZ"
log.info("question=%s", msg)
print("logged:", buf.getvalue().strip())
print("saved :", redact(msg))

Output (from running the code above):

logged: question=I'm [EMAIL], [PHONE], password: [SECRET] and my key is [SECRET]
saved : I'm [EMAIL], [PHONE], password: [SECRET] and my key is [SECRET]

What to watch for.

  • Pattern masking misses unusual formats; add exact-name masking for known people.
  • Mask before the data reaches any third-party tracing (recording each request step by step) or analytics tool (a function the AI can call, such as policy search).
  • Keep the original only where it's truly needed, with access control.

In plain terms: every note is run through a black marker before it's filed.

The parent post's demo showed DOB, phone and SSN (Social Security number) masked. See Step 6.

Trade-offs

  • Masking can remove something useful (a phone number the user wanted noted).
  • Regex (short for regular expression: a text pattern the code matches) is fast but imperfect; NER models catch more but cost more.

Interview answer

"Everything persisted, from memory to logs to traces (step-by-step records of each request: what ran, how long, what it cost), goes through a sanitization layer (code that masks personal details and secrets before anything is saved) first: pattern masking for emails, phones, IDs and keys, plus exact-name masking for known people, and a logging filter so nobody can forget. Saved state (everything the app must remember to continue correctly) outlives the chat, so that's where leaks happen."
