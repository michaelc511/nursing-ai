In plain words

A self-correction loop (checking the AI's answer and sending it back once to fix what failed) checks the AI's draft answer before the user sees it, and if a check fails, sends it back once with the exact failures to fix. Most mistakes get fixed on the second try; the rest (a common way for programs to talk over the web using URLs) are caught instead of shipped.

In plain terms: an editor who returns your draft with "this quote isn't in the source" circled, once, before it goes to print.

The problem it solves

Hallucination (The Grounding Failure) (the AI stating made-up facts when the answer isn't in front of it): a first draft can contain a quote or fact that isn't in the source.

The standard approach (in my words): ask the model to verify its answer against the provided context before returning the final result.

How to implement it (ServiceApps)

Illustrative example: no ServiceApps (a company platform for IT tickets, HR requests and help-center articles) instance is connected, so the scenario and data are made up. The code is a self-contained sketch; it was run on that made-up data on Nov 19, 2026, and the output below is from that run.

The setting. ServiceApps (a company platform for IT tickets, HR requests and help-center articles) Assist, an AI helper inside a company's ServiceApps (a company platform for IT tickets, HR requests and help-center articles) portal. Employees ask it IT and HR questions; it answers from knowledge-base (KB (knowledge base: a library of help articles)) articles, looks up the employee's own tickets (incidents (a ServiceApps ticket for something broken) like INC0012345) and requests, and keeps one conversation per employee and ticket.

The scenario. ServiceApps (a company platform for IT tickets, HR requests and help-center articles) Assist's first draft misstates what VPN error 809 means; the check catches it and the retry fixes it.

Steps.

  1. Generate a draft that includes its quotes.
  2. Verify in code: every quote must appear in the source.
  3. If it fails, retry once with the list of failures added to the prompt (the instructions and text given to the AI).
  4. If it still fails, return MISSING_INFO and hand over to a person.

The code (Python):

import re
SOURCE = "Error 809 means the VPN can't reach the server. Avoid guest Wi-Fi and restart the client."
attempts = iter(['Error 809 means your password expired. [quote: "your password expired"]',
                 'Error 809 means the VPN can\'t reach the server. [quote: "the VPN can\'t reach the server"]'])
def model(prompt): return next(attempts)         # stand-in for the AI call

def verify(draft):
    q = re.search(r'\[quote: "([^"]+)"\]', draft)
    return [] if q and q.group(1) in SOURCE else [f'quote not in source: "{q.group(1) if q else "none"}"']

def answer(question, max_retries=1):
    prompt = question
    for attempt in range(max_retries + 1):
        draft = model(prompt); fails = verify(draft)
        print(f"attempt {attempt + 1}: {'pass' if not fails else 'fail -> ' + fails[0]}")
        if not fails:
            return draft
        prompt = question + "\nYour previous answer failed these checks: " + "; ".join(fails) + ". Quote the source exactly."
    return "MISSING_INFO: couldn't verify an answer; a person will follow up."

print("final:", answer("What does VPN error 809 mean?"))

Output (from running the code above):

attempt 1: fail -> quote not in source: "your password expired"
attempt 2: pass
final: Error 809 means the VPN can't reach the server. [quote: "the VPN can't reach the server"]

What to watch for.

  • Verify in code where you can; asking the same model "are you sure?" is weaker.
  • Limit retries (one is usually enough) and cap cost per request.
  • Send the specific failures back, not just "try again".

In plain terms: draft, check, fix once, and only then answer; if it still can't be verified, a person takes over.

Trade-offs

  • Each retry costs another AI call and adds latency (how long it takes to respond).
  • Code checks only catch what they test (quotes, formats), not every wrong fact.

Interview answer

"Drafts go through a verify step in code, for example every quote must be in the source. On failure the model gets one retry with the exact failures listed, and if it still fails we return MISSING_INFO and hand off to a person. It fixes most errors and never ships an unverified one."
