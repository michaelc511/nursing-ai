In plain words

System prompt pinning (keeping the rules in a protected place that is sent on every call and never trimmed) keeps the AI's rules in a protected place that is sent on every call and never trimmed. Only the conversation history slides. However long the chat gets, the rules are always there.

In plain terms: the company handbook is bolted to the desk; only the pile of notes next to it gets cleared out.

The problem it solves

Sliding window truncation (silently dropping the oldest messages when the window is full) and Loss of instructional integrity (the AI losing its rules because they were pushed out of the window): if the rules are just the first message, trimming old messages throws the rules away first.

The standard approach (in my words): split the context into an immutable zone (rules) that is never truncated and a mutable zone (history) that slides.

How to implement it (ServiceApps)

Illustrative example: no ServiceApps (a company platform for IT tickets, HR requests and help-center articles) instance is connected, so the scenario and data are made up. The code is a self-contained sketch; it was run on that made-up data on Nov 19, 2026, and the output below is from that run.

The setting. ServiceApps (a company platform for IT tickets, HR requests and help-center articles) Assist, an AI helper inside a company's ServiceApps (a company platform for IT tickets, HR requests and help-center articles) portal. Employees ask it IT and HR questions; it answers from knowledge-base (KB (knowledge base: a library of help articles)) articles, looks up the employee's own tickets (incidents (a ServiceApps ticket for something broken) like INC0012345) and requests, and keeps one conversation per employee and ticket.

The scenario. ServiceApps (a company platform for IT tickets, HR requests and help-center articles) Assist's rule: never reset a password without identity verification. A chat reaches 10 turns and the window keeps only 6 messages.

Steps.

  1. Keep the rules as a separate field (the API's system field), not in the message list.
  2. Trim only the message list.
  3. Re-send the rules unchanged on every call.
  4. Test it: after a long chat, the rules must still be present.

The code (Python):

RULES = "You are ServiceApps Assist. Never reset a password without identity verification. Cite KB numbers."

def naive_window(history, limit=6):              # rules are just the first message, so trimming drops them
    msgs = [{"role": "system", "content": RULES}] + history
    return msgs[-limit:]

def pinned_window(history, limit=6):             # rules kept apart; only history is trimmed
    return {"system": RULES, "messages": history[-limit:]}

history = [{"role": "user" if i % 2 == 0 else "assistant", "content": f"turn {i}"} for i in range(10)]
n, p = naive_window(history), pinned_window(history)
print("naive : rules present?", any(m["role"] == "system" for m in n), "| first message:", n[0]["content"])
print("pinned: rules present?", bool(p["system"]), "| first message:", p["messages"][0]["content"])

Output (from running the code above):

naive : rules present? False | first message: turn 4
pinned: rules present? True | first message: turn 4

What to watch for.

  • Keep the pinned rules short; they're paid for on every call (prompt caching (the AI provider reusing an unchanged prompt start, so calls are cheaper and faster) helps).
  • Pinning keeps the rules present, not necessarily prominent; long chats may still need a reminder (see Recursive Goal Injection (repeating a short reminder of the rules before every AI answer)).
  • Add a test that a long conversation still carries the rules.

In plain terms: the rulebook never leaves the desk, no matter how many notes pile up.

In NurseOps Now

Built. The rules (backend/app/prompts/assist_v1.md) go in the API's system field on every call, and only the history list is trimmed to 10 turns. See Step 2.

Trade-offs

  • Pinned rules cost tokens (pieces of words the AI reads and writes; cost is per token) on every call; cache them.
  • Big rule sets crowd the window; keep them tight.

Interview answer

"I never put the rules in the trimmable history. They go in the system field on every call, and only the conversation slides. That's the fix for the classic failure where a long chat pushes the policy (the health plan's written rules for when a test is covered) out and the agent (an AI that chooses which tools to use to answer) stops following it."

All data in this post is made up. No real people, tickets or patient data.
