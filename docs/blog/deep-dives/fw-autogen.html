In plain words

AutoGen (Microsoft) builds apps from agents (an AI that chooses which tools to use to answer) that talk to each other. Each agent (an AI that chooses which tools to use to answer) has a model context (what it sends to the model, with ready-made limits), optional memory stores it consults before answering, and save/load state (everything the app must remember to continue correctly) to pause and resume.

In plain terms: each agent (an AI that chooses which tools to use to answer) has a short notepad with a fixed number of lines, an optional reference binder, and can photocopy its notepad to continue later.

What it gives you for memory

From the official memory docs (AutoGen memory docs), checked on Nov 19, 2026:

  • Short-term: BufferedChatCompletionContext(buffer_size=N), TokenLimitedChatCompletionContext(model_client, token_limit=...) (experimental), HeadAndTailChatCompletionContext(head_size, tail_size), UnboundedChatCompletionContext.
  • Persistence: await agent.save_state() / load_state(state), also for teams; the state (everything the app must remember to continue correctly) is a dict you store yourself.
  • Long-term: the Memory protocol (add, query, update_context, clear) with ListMemory, ChromaDBVectorMemory, RedisMemory, Mem0Memory.
  • Deleting: memory.clear() (the whole store), model_context.clear(), team.reset(); no TTL or per-user delete in the docs.

How to implement it (ServiceApps)

Illustrative example: made-up data, no ServiceApps (a company platform for IT tickets, HR requests and help-center articles) instance. The code was run as shown; the model is a scripted stand-in, so no API key (a secret code that lets the app use a paid service) is needed.

The scenario. ServiceApps (a company platform for IT tickets, HR requests and help-center articles) Assist as one AutoGen agent (an AI that chooses which tools to use to answer) with a 4-message buffer and a small preference memory. The model is AutoGen's replay client (scripted replies), so the example runs without an API key (a secret code that lets the app use a paid service).

Steps.

  1. Give the agent (an AI that chooses which tools to use to answer) a model context with a limit (BufferedChatCompletionContext).
  2. Attach long-term memory (memory=[ListMemory()] or a vector (text turned into a list of numbers so similar meanings sit close together) memory).
  3. After each turn, save_state() and store the JSON (a simple text format for structured data) under your session key.
  4. To resume, create the agent (an AI that chooses which tools to use to answer) and load_state(); to forget, clear() the memory and delete the saved state (everything the app must remember to continue correctly).

The code (Python):

import asyncio, json
from autogen_agentchat.agents import AssistantAgent
from autogen_core.memory import ListMemory, MemoryContent, MemoryMimeType
from autogen_core.model_context import BufferedChatCompletionContext
from autogen_ext.models.replay import ReplayChatCompletionClient

async def main():
    replies = ["Which error code do you see?", "809: the VPN can't reach the server. Avoid guest Wi-Fi.", "Try your phone hotspot."]
    prefs = ListMemory()                                                          # long-term memory (7.3)
    await prefs.add(MemoryContent(content="User prefers short bullet answers", mime_type=MemoryMimeType.TEXT))
    agent = AssistantAgent("assist", model_client=ReplayChatCompletionClient(replies),
                           system_message="You are ServiceApps Assist. Cite KB numbers.",
                           model_context=BufferedChatCompletionContext(buffer_size=4),   # short-term limit (7.1)
                           memory=[prefs])
    for q in ["My VPN keeps dropping", "Error 809", "I'm on hotel Wi-Fi"]:
        r = await agent.run(task=q)
        print(f"{q!r:24} -> {r.messages[-1].content}")
    kept = await agent._model_context.get_messages()                              # what the next call would see
    print("model context keeps:", len(kept), "messages (buffer_size=4)")
    state = await agent.save_state()                                              # serialization (7.3)
    blob = json.dumps(state)
    print("saved state:", len(blob), "chars of JSON, keys:", sorted(state))
    agent2 = AssistantAgent("assist", model_client=ReplayChatCompletionClient(["(resumed)"]),
                            model_context=BufferedChatCompletionContext(buffer_size=4))
    await agent2.load_state(json.loads(blob))
    print("restored context:", len(await agent2._model_context.get_messages()), "messages")
    await prefs.clear()
    print("memory after clear():", (await prefs.query("anything")).results)

asyncio.run(main())

What to watch for.

  • save_state() gives you a dict; where it's stored, under which key, and for how long is your job.
  • memory.clear() clears everything in that store; keep one store per user if you need per-user deletion.
  • No redaction: mask before memory.add().

Use both (complement), with your rules on top:

  • Three-Tier Memory: Episodic (Experience Log) (a record of what happened, step by step): ListMemory keeps a chronological list; the audit log (a permanent record of who did what and when) is yours
  • Agentic Outcome: Strict State Serialization (saving state so work can pause, crash and resume without loss): save_state() / load_state() return a dict; storing it is yours
  • System Prompt Pinning (keeping the rules in a protected place that is sent on every call and never trimmed): HeadAndTailChatCompletionContext can always keep the first messages
  • Entity Extraction (pulling key facts (names, dates, IDs) out of text into a structured record): Mem0Memory extracts facts (an outside service)
  • The Hot/Cold State Architecture (splitting memory into what is in the current call (hot) and what is saved for later (cold)): Model context is hot; Memory and saved state (everything the app must remember to continue correctly) are cold

  • The Rehydration Pattern (fetch saved state, keep only what's relevant, and put it back into the next call): load_state(); memory adds relevant items to the context
  • GDPR Right to Be Forgotten (a person's right to have their stored data deleted (from the EU's GDPR law)): memory.clear() clears a whole store, not one user

Trade-offs

  • Ready-made window limits (including a token (the unit the AI reads and is billed by, about three quarters of a word) limit), but persistence is a dict you manage.
  • Multi-agent conversations multiply memory: each agent (an AI that chooses which tools to use to answer) has its own context.

Interview answer

"In AutoGen I'd give each agent (an AI that chooses which tools to use to answer) a bounded model context, buffered or token-limited, attach vector (text turned into a list of numbers so similar meanings sit close together) memory for long-term facts, and save_state after each turn to my own store under a session key. Clearing and retention are mine to design, because memory.clear() wipes a whole store."
